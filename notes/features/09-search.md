# Поиск в текущей папке (Ctrl+F)

Статус: 📝

## Что делает

- **Ctrl+F** показывает поле ввода и ставит в него фокус.
- Список текущей папки фильтруется по мере ввода: остаются элементы,
  у которых имя **содержит** введённую строку (`Contains`).
- Ищется только в текущей папке, без рекурсии, по уже загруженному списку.
  Диск повторно не читается.

## Поведение

- Регистр не учитывается: `Contains(query, StringComparison.OrdinalIgnoreCase)`.
- Пустая строка — показывается весь список.
- **Esc** в поле — очистить, скрыть поле, вернуть фокус в список.
- **Enter / ↓** в поле — фокус в список на первый найденный.
- Повторный Ctrl+F при открытом поле — фокус и выделение всего текста.
- Переход в другую папку сбрасывает поиск и скрывает поле.
- Статус: «Найдено N из M» при непустом запросе.

## Как устроено (план)

- VM: полный список `_all` (результат `TryList`) + свойство `Filter`.
  Сеттер `Filter` → пересобрать `Entries` из `_all`. `Apply` сохраняет
  `_all`, сбрасывает `Filter` и заполняет `Entries`.
- VM: `IsSearchVisible` — видимость поля (`IsVisible="{Binding IsSearchVisible}"`).
- View: `TextBox` над списком, `Text="{Binding Filter}"` (TwoWay).
- Горячая клавиша: `KeyBinding` на окне или обработка в `OnKeyDown`
  (`Key.F` + `HotkeyConfiguration.CommandModifiers` — на macOS это Cmd).
  После показа поля — `searchBox.Focus()` (элемент с `x:Name`, поле
  генерируется в `InitializeComponent`).
- Esc/Enter — `KeyDown` поля в code-behind.

## Зависимости и пересечения

- Backspace в списке = «вверх»: в поле поиска он должен стирать символ.
  Обработчик `OnListKey` висит на ListBox, конфликта нет — проверить.
- Copy-paste / выделение работают по отфильтрованному `Entries`:
  Ctrl+A → Ctrl+C копирует только найденное (это и ожидаемо).
- После paste / refresh фильтр сохранять (перечитывание той же папки
  не должно сбрасывать поиск, в отличие от перехода в другую).
